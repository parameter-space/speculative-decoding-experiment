# Compatibility and provenance

- Upstream: ETH-DISCO/SD-square @ `00f578aaabc4d48efd9a10ccd0e8d0297bdc6e07`, untouched.
- Checkpoint: peerrh/llama-3.1-8b-steered @ `af46f8c124bce8367746d97954b631af18119133`; SHA256 in configs/smoke.json.
- The official README recommends Python 3.12; `.python-version` says 3.13 and pyproject requires >=3.13. `src/data.py` contains Python-3.12 `type Alias = ...` syntax, so the server's Python 3.11 cannot import main.py as-is. This harness imports scripts directly using a separate Python3.12 environment, not `pip install` of the upstream project. Its tiny-model tests exercise this configuration. K2 real-checkpoint compatibility remains unverified until run.
- The four upstream dependency pins are retained. PyTorch 2.5.1+cu121 is selected for the already verified A6000 driver. Auxiliary packages are pinned in requirements; actual full package versions are captured per run. No silent latest-version fallback.
- Loading changes only: canonical-case model IDs, fixed resolved HF revisions, CPU tensor-only mmap checkpoint loading, strict key/shape validation, explicit SDPA backend. The official loader has implicit cache/precision/device behavior and unsafe unrestricted checkpoint deserialization; this wrapper does not copy it verbatim.
- Actual precision follows official eval: Target FP16 weights, Drafter and guidance BF16 weights, CUDA BF16 autocast. Metric softmax is explicitly FP32. The earlier general BF16 plan is refined here to preserve official evaluation's choices; all weight storage remains 16-bit. Do not describe this as a uniform-BF16 reproduction.
- Snapshot hooks do not modify tensor outputs. Capture stops after first proposal logits at a normal round >=2, before sampling. Source G is selected from the preceding real verifier call using actual accepted count; physical masked cache slots and all pending D tokens are preserved.
- Tensor source layers are **pre-block** states in this pinned implementation. This is verified by an actual tiny-model hook test rather than inferred from layer labels.
- The Target guide projection is registered under both root and Target decoder as a shared object. Total model bytes use unique parameter iteration, not a sum of overlapping module totals.
- Slurm execution checks are in shell launchers; no installation, data preparation or model run is permitted on master. `my_env` is not overwritten. No uploads, telemetry requests from the harness, W&B sessions, license acceptance, or dynamic code execution from dataset/model repositories.
- CPU tests cannot establish CUDA numerical tolerances, real checkpoint load success, real tokenization, GPU peak memory, or scientific utility. Those remain explicit K2 gates.
- Two-GPU mode launches separate processes, each seeing one GPU from the original Slurm CUDA_VISIBLE_DEVICES mask. Each process loads the complete model pair and performs the same baseline/calibration; evaluation cases are disjoint and A/B pairs stay together. No cross-GPU tensor communication or model split is introduced. CPU partition/merge tests do not establish actual concurrent K2 execution.
